## 공통 UI 원칙
- 모든 날짜 입력은 **날짜 선택 UI(Date Picker)** 사용, 텍스트 직접 입력 없음
- 금액 입력·저장은 **공급가 기준**, 표시할 때 아래에 부가세 포함 금액을 작게 병기
  > 150,000원
  > <small>VAT 포함 165,000원</small>
- 천 단위 구분 표시, **무상** 체크 시 0원 처리 + 사유 입력
- 화면 대상: PC 웹 (모바일 대응은 추후 검토)

## 동시 편집 처리
> 일반적인 업무 시스템(세일즈포스·지라 등) 방식인 **저장 시점 충돌 감지(낙관적 잠금)** 채택. 실시간 공동편집·편집 잠금은 사용하지 않음

- 편집 단위: 섹션(기본정보 섹션 카드, 계약, 비용 항목 1건 등)
- 편집 시작 시 해당 데이터의 최종 수정 시각을 기억 → [저장] 시 그 사이 다른 사용자가 수정했으면 저장 차단
- 충돌 모달
  > "홍길동님이 3분 전에 이 정보를 수정했습니다. 최신 내용을 확인한 후 다시 저장하세요."
  > 변경된 필드: 연락처, 이메일 (최신값 / 내 입력값 나란히 표시)
  > [최신 내용으로 다시 편집] [취소]
  - 덮어쓰기 버튼은 두지 않음(다른 사람 수정 내용 유실 방지)
- 충돌이 생기지 않는 동작: 히스토리 기록, 체크리스트 체크, 파일 업로드, 항목 추가 → 즉시 저장
- 상태 변경은 모달 제출 시 현재 상태가 바뀌었으면 "이미 OO 상태로 변경되었습니다" 안내 후 새로고침

## 1. 상태값 정의

| 상태 | 의미 | 전환 시 입력 |
|---|---|---|
| 진행대기 | 상담·견적 진행, 계약 전 — **시작 상태**(직접 등록·인바운드 문의 전환 시 기본값) | - |
| 도입준비 | 계약 체결 후 설치·세팅 진행 중 | 계약정보(계약일·시작일·종료일) |
| 체험중 | 무료 체험/PoC (반납 조건) | 체험 시작일·종료일 |
| 사용중 | 정식 서비스 이용 중 | - (아래 전환 규칙) |
| 계약종료 | 계약 기간 만료로 종료 | 종료일 |
| 계약해지 | 계약 기간 중 중도 해지 | 해지일·사유 |
| 미전환 | 문의 후 계약으로 이어지지 않음 | 사유 |
| 기타 | 예외 | 사유 |

### 단계별 필수 입력 항목
상태를 바꿀 때 아래 항목이 비어 있으면 **전환 불가 모달**에 누락 항목을 나열하고 해당 위치로 이동 링크 제공
> "사용중으로 전환하려면 아래 항목을 먼저 입력하세요. · 계약서 업로드 · 서비스 페이지 URL · 청구일" [입력하러 가기] [닫기]

| 시점 | 필수 항목 |
|---|---|
| **등록 (진행대기)** | 시설명 · 시설 유형 · 지역 · 내부 담당자 · 시설 담당자 1명(이름·연락처) · 대표 담당자 1명 이상 |
| **도입준비** | **고객사 코드** · 주소 · 계약(계약일·시작일·종료일·계약 인원·제공 장비 수량) · **계약 금액**(구축형: 장비 단가·납부 방법 / 구독형: 밴드 월 단가) · 사업자 정보(법인명·사업자등록번호·대표자명) · 설치 예정일 |
| **체험중** | **고객사 코드** · 주소 · 체험 시작일·종료일 · 체험 장비 수량 |
| **사용중** | 도입준비 필수 항목 전체 + **계약서 · 디바이스 인수증** 업로드 + 서비스 페이지 URL · 관리자 계정 1개 이상(서비스 계정) + 정산 정보(청구일·결제 수단·세금계산서 발행 여부·발행 이메일) |
| **계약종료** | 종료일 |
| **계약해지** | 해지일 · 사유 |
| **미전환 · 기타** | 사유 |

- 고객사 코드: 문의·진행대기 단계에서는 비워둘 수 있음, **입력 후 변경 불가 · 중복 불가**
- 체크리스트 미완료는 차단하지 않고 확인창만 표시(아래)
- 진행대기에서 바로 사용중으로 가는 경우 등 단계를 건너뛰어도 도착 상태 기준 필수 항목을 모두 확인

### 전환 규칙
- **상태 전환은 수동이 원칙.** 시스템 자동 처리는 두 가지뿐: ① `갱신 취소` 건 종료일 도래 시 계약종료 전환 ② 미조치 건 종료일 경과 시 동일 조건 자동연장 (4-5)
- **필수 항목 차단**: 위 표의 도착 상태 필수 항목 누락 시 전환 불가 모달(누락 항목 나열)
- **사용중 전환 — 체크리스트 확인창**: 미완료 항목이 있어도 전환 가능, 확인창만 표시
  > "입소자 정보, 시설 정보 확인이 완료되지 않았습니다. 사용중으로 전환할까요?" [취소] [전환]
  - 미완료 항목명 나열(3개 초과 시 "외 N건"), 전환 시 히스토리에 미완료 항목 함께 기록
- 모든 상태 변경은 히스토리 자동 기록(이전→이후, 변경자/시스템, 일시, 사유)
- **고객사 삭제 기능 없음** — 더 이상 관리하지 않는 건은 미전환·계약종료·기타 등 상태로 정리

### 기존 데이터 이관
| 엑셀 | → 신규 |
|---|---|
| 문의 접수 | 인바운드 문의함 (미처리 문의) |
| 진행 중 | 도입준비 |
| 완료 | 사용중 (종료일 지난 건은 계약종료) |
| 중지 | 미전환 |

## 2. 권한 · 계정

| 기능 | 관리자 | 일반 |
|---|:-:|:-:|
| 고객사·계약·비용·문서·체크리스트·히스토리·인바운드·내보내기·알림 기준 설정 | ✅ | ✅ |
| **사용자 계정 관리** (발급·권한 변경·비활성화·비밀번호 재설정 메일) | ✅ | ❌ |

**계정 정책**
- 계정 **삭제 불가**, 비활성화만 가능 → 작성 기록·히스토리 영구 유지
- 아이디(이메일) **변경 불가**, 이름·연락처는 변경 가능
- 비밀번호: 본인 변경 가능 + 관리자가 재설정 메일 발송 가능
- 비활성 계정: 로그인 차단, 기록에는 "(비활성) 이름"으로 표시
- 비활성 사용자가 내부 담당자인 고객사는 리스트에 "담당자 재배정 필요" 표시

**히스토리 정책**
- 자동 기록: 누구도 수정·삭제 불가
- 수동 기록: 작성자 본인만 수정 가능(관리자 포함 타인 불가), 수정 시 "수정됨" 표시

**삭제 정책 (휴지통 없음)**
- 삭제 대상: 파일, 시설 담당자, 수동 히스토리, 비용·옵션·추가기기 항목
- 삭제 시 확인창 → 영구 삭제, 해당 고객사 히스토리에 "OO 삭제" 자동 기록

## 4. 기능 상세

### 4-1. 고객사 리스트
- **상태 탭**: 전체 / 진행대기 / 도입준비 / 체험중 / 사용중 / 계약종료 / 계약해지 / 미전환 / 기타 — 탭별 건수
- **검색**: 시설명, 고객사 코드, 시설 담당자명·연락처, 사업자등록번호
- **상세 필터**: 지역, 시설 유형, 내부 담당자, 등록일 기간, 계약 종료일 기간, 알림 대상(알림 유형 전체)
- **컬럼**: 모든 탭 동일 (탭별 전용 컬럼 없음, 상세 정보는 상세 페이지에서 확인) — 화면정의서 1-3 참고
  - 서비스 페이지 이동: 버튼 클릭 시 해당 고객사 서비스 URL 새 탭 열기, URL 미등록 시 비활성
- 행 배지: 갱신 확인 필요 / 갱신 취소됨 / 알림 대상
- 20개/페이지, 전체 건수, 컬럼 정렬, 필터 결과 엑셀 내보내기

### 4-2. 고객사 상세 — 상단 요약 영역 (모든 탭 공통)
- 시설명 · 코드 · 시설 유형 · 상태 배지 · 갱신 배지
- **[서비스 페이지 이동]** 버튼 (URL 미등록 시 비활성 + "URL 등록" 안내)
- 요약: 대표 담당자, 내부 담당자, 계약 기간, 계약 인원, 월 비용(이번 달 기준), 대표 관리자 계정(사용 계정 수)

### 4-4. 계약 · 비용

화면 순서: **계약 내용 → 옵션상품 → 추가 기기 제공 → 비용 항목(최종 정리)**

**계약 내용**
| 항목 | 설명 |
|---|---|
| 기본 | 계약일, 시작일, 종료일([시작일부터 1년·2년] 버튼), 계약 인원, 메모 |
| 자동연장 | 연장 안 함 / 6개월 / 1년 / 2년 / 직접입력(개월) — **계약마다 연장 기간이 다름**, 종료일 경과 시 이 기간만큼 연장 (갱신 전 알림 정책은 유지) |
| 계약 유형 | **구축형**(장비 구매) / **구독형**(밴드당 월 과금) |
| 제공 장비 | 허브 · 밴드 · 충전기 수량 (어댑터는 계약에서 제외 — 체험·추가 기기·회수 내역에는 있음) |
| 구축형 금액 | 허브·밴드·충전기 **단가** → 구축 총액 = Σ(단가 × 수량) → 납부: **일시납**(청구월) 또는 **분납**(시작월 + 개월 수, 월 분납액 = 총액 ÷ 개월 수 원 단위 내림, 남는 금액은 마지막 회차) |
| 구독형 금액 | **밴드 월 단가** → 월 구독료 = 단가 × 밴드 수, 계약 기간 동안 매월 |
| 가입비 | 선택(두 유형 공통), **1회성** — 계약 시작월(첫 달) 매출에만 포함 |
| 월 관리비 | 선택(두 유형 공통) + **청구 시작월**(월 단위: 계약 시작월·6개월 후·1년 후·2년 후 버튼 또는 "계약 시작 n개월 후" 입력) — 시작월부터 매월, 계약 종료월에 묶지 않음 |

**비용 항목 (최종 정리 표)** — 계약 내용·옵션상품·추가 기기의 금액이 **자동 줄**로 정리되고, 구축비·기타 장비비 등은 **[추가]로 직접** 넣음(일시/월, 무상 가능)
| 직접 추가 필드 | 설명 |
|---|---|
| 비용 유형 | 일시(청구월 1개) / 월(계약 기간 동안 매월) |
| 항목명 | 예) 구축비, 설치비, 기타 장비비, 직접입력 |
| 금액 | 무상 가능(무상 사유 필수) |

- 표 아래 합계: **일시 비용 합계**, **이번 달 월 비용**
- 요약·리스트의 **월 비용** = **이번 달에 청구되는 월 비용** 합계 — 구독료 + 분납액(분납 기간) + 관리비(시작월 이후) + 직접 추가 월 비용 + 월 옵션상품(제공월 이후) (월 비용 줄이 없으면 "-")
- 계산 위치: `lib/billing.ts` (3단계 월별 청구도 같은 계산 사용)

**표 컬럼 통일**: 비용 항목·옵션상품·추가 기기 제공 3개 표는 같은 컬럼 순서와 폭을 사용 — `항목 · 상세 · 수량 · 일자 · 유형 · 금액 · 메모 · [수정][삭제]` (해당 없는 칸은 "-")

**옵션상품 (태블릿·TV 등)** — 여러 건 등록, 장비 탭과 같은 데이터(어느 탭에서 추가해도 양쪽에 표시, 금액은 계약·비용 탭에서 관리)
| 필드 | 설명 |
|---|---|
| 상품 구분 | 태블릿 / TV / 기타(직접입력) |
| 제품명·모델 | 공급된 제품 기록 |
| 수량 | |
| 제공일 | Date Picker |
| 제공 가격 | 비용 유형(일시/월) + 금액, 무상 가능 |
| 메모 | |

**추가 기기 제공** (분실·파손·증설 등) — 여러 건 등록
| 필드 | 설명 |
|---|---|
| 기기 종류 | 밴드 / 허브 / 차저 / 기타(직접 기기명 입력) |
| 수량 | |
| 제공 사유 | 분실 / 파손 / 증설 / 기타 |
| 제공일 | Date Picker |
| 제공 비용 | 금액 입력, **무상** 체크 가능(무상 시 사유 필수) |
| 메모 | |
- 장비관리 연동 후: 제공 시 실제 장비 매핑 연결 (장비관리 문서에서 정의)

### 4-5. 계약 갱신 (자동연장 기준)
> **갱신 = 현재 계약의 종료일 연장** — 새 계약을 만들지 않음. 시작일·금액 조건은 그대로, 조건이 바뀌면 계약 내용 [수정]
1. 종료일 D-60(설정값) 도래 → 리스트·상세·대시보드 **갱신 확인 필요** 배지 + 🔔 알림
2. 배지 또는 **[계약 갱신]** 버튼 → **계약 갱신 · 종료일 변경** 모달
   - **[+6개월] [+1년] [+2년]**: **현재 종료일 기준**으로 새 종료일 계산 (예: 12/31 계약을 11/15에 +1년 → 다음 해 12/31, 누른 날짜와 무관)
   - 또는 날짜 직접 선택 → [갱신] → 종료일 변경, 배지 제거
   - **줄이기 가능**: 갱신했다가 취소된 경우 등 — [직전 갱신 되돌리기(이전 종료일)] 버튼 또는 날짜 선택 → [종료일 변경]
3. **[갱신하지 않음(갱신 취소)]**: 사유 입력 → 배지 **갱신 취소됨**(회색) → 종료일 도래 시 상태 **계약종료 자동 전환**
   - 상세 상단 안내 문구: "2026.12.31에 계약이 종료됩니다. <u>계약 기간 변경</u>"
   - 같은 모달에서 종료일 변경(그 날짜에 계약종료) 또는 **[갱신 취소 철회]**(→ 다시 갱신 확인 필요)
4. **아무 조치 없이 종료일 경과** 시: 종료일을 **설정한 연장 기간**만큼 **자동연장** + **경고 배지**(빨강, 자동연장 미승인)
   - 모달: "자동연장되었습니다: 종료일 2026.12.31 → 2027.12.31"
     - **[자동연장 승인]** → 배지 제거, 연장된 종료일 유지
     - **[계약 종료로 변경]** → 종료일을 자동연장 전 날짜로 되돌리고 그 날짜로 계약종료
     - 직접 종료일을 바꿔도 확인한 것으로 봄
- **자동연장 N(연장 안 함)** 계약: 종료일이 지나면 갱신 취소와 같이 **계약종료 자동 전환**(D-60부터 갱신 확인 필요 배지)
- 갱신·종료일 변경·취소·철회·자동연장·승인 모두 히스토리 자동 기록(이전 → 이후 종료일)
- 금액: 구독료·관리비는 늘어난 종료일까지 계속 청구, 가입비·구축 일시납은 이미 지난 청구월이라 다시 청구되지 않음

### 4-5-1. 체험 종료 처리
1. 체험 종료일 D-7 → 리스트·상세·대시보드 **체험 종료 확인 필요** 배지(주황) + 🔔 알림
2. 배지 클릭 → 체험 종료 모달
   > "체험이 YYYY.MM.DD에 종료됩니다. 체험 결과를 선택하세요."
   - **[계약 전환]** → 계약정보 입력 폼(체험 장비를 계약 장비로 체크 시 수량 채움) → 계약 저장 후 **도입준비 전환 시도**: 다른 필수 항목이 비어 있으면 계약은 저장된 채 체험중 유지 + 누락 항목 목록(입력 후 상태 배지에서 전환), 전환되면 체험 결과 = 계약 전환
   - **[체험 연장]** → 체험 종료일 변경(Date Picker), 배지 제거 후 새 종료일 기준으로 다시 알림
   - **[미전환 처리]** → 사유 입력 → 상태 미전환 + **장비 회수 체크리스트** 생성
3. 아무 조치 없이 종료일 경과 → 상태는 **체험중 유지**(결과를 알 수 없으므로 자동 전환 안 함) + 배지 빨강 **체험 기간 경과**, 모달은 동일
- 모든 선택은 히스토리 자동 기록

### 4-5-2. 장비 회수·종료 체크리스트
장비가 나가 있는 고객사가 종료되면 회수·정리 누락을 막기 위해 체크리스트를 생성

| 생성 시점 | 체크 항목 |
|---|---|
| **미전환** (체험중에서 전환된 경우) | 장비 회수 |
| **계약종료 · 계약해지** | 장비 회수 · 늘케어 계정 비활성화 · 입소자 명단 등 개인정보 파기 · 최종 청구 확인 |

- **장비 회수** 항목: 기기별(밴드·허브·차저·어댑터·옵션상품) 제공 수량 / 회수 수량 입력, 회수일(Date Picker), 미회수 사유(분실·파손·기타)
  - 제공 수량 = 계약 장비 수량 + 추가 제공 기기 + 체험 장비 (장비관리 연동 후 매핑 장비 기준으로 자동 표시)
  - 체험 장비는 계약으로 전환되지 않은 체험만 포함 (계약 전환된 체험 장비는 계약 장비 수량에 포함되므로 중복 제외), 옵션상품은 품목별 1줄
- 항목별 완료 체크·완료일·완료자 기록, 전체 완료 시 배지 제거
- 미완료 상태로 N일(기본 14일) 경과 → **장비 미회수** 알림
- 화면: 상세 상단 안내 배너 + `도입 체크리스트` 탭 명칭을 `체크리스트`로 변경해 도입·종료 체크리스트를 함께 표시

### 4-6. 월별 청구 관리
> 현재: 비용·청구를 수동 관리 → 월별로 청구 여부를 기록하고 세금계산서를 업로드
> 향후: 효성CMS API 연동으로 출금·입금 현황 자동 반영 (데이터 구조를 지금부터 연동 전제로 설계)

**청구 건 생성**
- 매월 1일, 사용중 고객사마다 해당 월 **청구 건** 자동 생성 (상태 변경이 아닌 데이터 생성)
  - 구현: 매일 배치에서 해당 월 청구 건이 없으면 생성 (데이터모델 4장)
- 예정 금액 = 해당 월 월 비용 합계 + 청구월이 해당 월인 일시 비용(계약·옵션상품·추가기기)
- 예정 금액은 생성 시점 값으로 고정, 필요 시 수동 조정(조정 사유 입력)
- 청구 대상은 **사용중** 고객사만 (체험중·도입준비 등은 생성하지 않음), 예정 금액이 0원이면 만들지 않음
- 분납 마지막 회차에 나누어떨어지지 않은 나머지 금액을 더함
- 청구 관리 화면의 [이번 달 청구 건 만들기] 버튼으로 배치를 기다리지 않고 바로 생성 가능(이미 있으면 건너뜀)

**청구 건 필드**
| 필드 | 설명 |
|---|---|
| 청구월 | YYYY-MM |
| 예정 금액 | 공급가 + VAT 포함 병기, 항목별 내역 펼쳐보기 |
| 청구 상태 | 청구 전 / 청구 완료 / 입금 확인 / 미납 — 수동 방식은 드롭다운으로 직접 변경 |
| 세금계산서 | 파일 업로드·교체·삭제 — 업로드 시 상태 `청구 완료` + 발행일 오늘로 자동 입력(수정 가능) |
| 발행일 | 수동 방식에서 직접 입력(Date Picker) |
| 입금일 | 수동 방식에서 직접 입력(Date Picker) |
| 처리 방식 | 수동 / CMS (현재는 모두 수동) |
| 메모 | |

**화면**
- 고객사 상세 `청구` 탭: 월별 청구 건 목록(최신순), 월별 세금계산서 업로드·상태 변경
- **청구 관리** 메뉴: 월 선택 → 해당 월 전체 고객사 청구 건 목록
  - 필터: 청구 상태, 세금계산서 미업로드
  - 합계: 예정 금액 / 청구 완료(청구 전이 아닌 건 전체) / 입금 확인 / 미납
  - 세금계산서 일괄 업로드 없이 행별 업로드, 목록 엑셀 내보내기(4단계)
- 상태 변경·파일 업로드·금액 조정 모두 히스토리 기록

**효성CMS 연동 대비 (2차)**
- 고객사 정산 정보에 `CMS 회원번호`, `CMS 연동 여부` 필드 미리 확보
- 결제 수단이 CMS이고 연동된 고객사는 청구 건의 처리 방식 = `CMS`
  - 출금 요청·결과(성공/실패)·입금일을 API로 받아 청구 상태 자동 갱신, 출금 실패 시 `미납` + 알림
  - 수동 건과 CMS 건이 같은 청구 건 구조를 쓰므로 화면·통계는 그대로 유지
- 세금계산서 발행 자동화는 연동 단계에서 효성CMS 제공 범위 확인 후 결정
- 연동 방식(API 사양·인증·호출 주기)은 효성CMS 계약 후 별도 정의

### 4-7. 체크리스트 (도입)
- 고정 11개: 입소자 정보 · 시설 정보(wifi 등) · 조감도 · 개인정보 동의 · 계약서 날인 · 장비 매핑 · 계정 생성 · 밴드 라벨링 · 설치 · QA · 태블릿&TV
- 항목별: 완료 체크, 완료일·완료자 자동 기록 / 모든 체크는 수동 / 메모 없음
- 완료일은 실제 완료한 날로 수정 가능(Date Picker, 오늘 이후 불가), 완료자는 유지, 수정 내역은 히스토리 기록 — 회수·종료 체크리스트도 동일
- 체크 해제 시 확인창 → 완료일·완료자 삭제, 해제 기록은 히스토리에 남김
- 항목은 DB 마스터로 관리 → 향후 추가 대비
- 상단 일정 영역: 설치 예정일 (미팅일은 기록하지 않음 — 미팅은 히스토리에 '미팅' 유형 수동 기록)

### 4-9. 히스토리 (히스토리 탭: 넓게 읽기 / 우측 패널: 다른 탭 보면서 입력)
- **자동 기록**: 등록, 상태 변경(수동/시스템), 계약 생성·갱신·갱신 취소·자동 연장, 체험 연장·결과 처리, 회수·종료 체크리스트 체크, 입소자 명단 다운로드, 비용·옵션상품·추가기기 등록/수정/삭제, 청구 상태 변경·세금계산서 업로드·금액 조정, 체크리스트 체크/해제, 파일 업로드/교체/삭제, 담당자 변경·삭제, 서비스 계정 추가·상태 변경·삭제, 와이파이·서비스 계정 비밀번호 조회
- **수동 기록**: 영업 활동 (유형: 미팅/통화/메일/방문/기타, 날짜, 내용, 작성자)
- 최신순 타임라인, 유형 필터(전체/자동/수동)

### 4-10. 알림
**알림 기준 (설정 > 알림 기준, 기본값)**
| 알림 | 대상 | 기본 기준 |
|---|---|---|
| 갱신 확인 필요 | 사용중 | 계약 종료일 D-60 |
| 진행대기 장기 체류 | 진행대기 | 마지막 활동 후 14일 |
| 체험 종료 확인 필요 | 체험중 | 체험 종료일 D-7, 경과 |
| 장비 미회수 | 미전환·계약종료·계약해지 | 회수·종료 체크리스트 미완료 14일 경과 |
| 도입 지연 | 도입준비 | 설치 예정일 경과 |
| 미처리 문의 | 인바운드 문의함 | 접수 후 3일 |
| 청구 미처리 | 청구 건 | 고객사 청구일 + 5일까지 세금계산서 미업로드 |
| 미납 | 청구 건 | 상태가 미납인 건 |
| 자동연장 확인 필요 | 사용중 | 종료일이 자동연장된 계약 (확인 또는 되돌리기 전까지) |
| 담당자 재배정 필요 | 전체 | 담당자가 비활성 사용자 |

- 청구일은 고객사별 `비용 청구일`(계약 내용에서 설정, 없으면 매월 1일)
- 심각도: 빨강(기한 경과·미납·자동연장 확인) → 주황(기한 임박·지연) → 회색(갱신 취소 예정)
- 매일 배치 외에도 🔔·대시보드·고객사 목록을 열 때(1분 간격) 다시 계산, 알림 기준 저장 시 즉시 재계산
- 고객사 목록에 알림 열·알림 필터 제공

- 수신자 구분 없음 — 모든 사용자에게 동일 표시
- 상단 🔔: 새 알림 있으면 점 표시 → 클릭 시 알림 모달(유형 · 시설명 · 한 줄 내용) → 항목 클릭 시 고객사 상세로 이동
- 새 알림 여부는 사용자별 판단(모달 열면 확인 처리)
- 조건 해소 시(상태 변경, 기한 갱신 등) 알림 자동 해제

### 4-11. 인바운드 문의함
- 모든 채널 문의를 `문의` 단위로 수집 → 검토 후 `고객사로 전환`(진행대기 상태로 생성) 또는 `제외`
- 전환한 문의는 문의함 목록에서 빠짐(탭: 미처리 / 제외)
- 중복 의심(시설명·연락처 일치) 건도 버튼은 동일 → 전환 시 "중복 의심되는 시설입니다. 전환하시겠습니까?" 확인창(기존 고객사 정보 표시)
- 행 클릭 → 문의 상세(원문 전체·연락처·규모) 모달, 상세에서도 전환·제외 가능
- 채널 필드로 향후 채널 확장
- 1차: 구글폼 → Apps Script(`onFormSubmit`) → 시스템 API / 2차: G메일 이메일 문의 연동

### 4-12. 대시보드

- 알림 목록: 한 알림 = 한 행 `[알림 배지] 시설명 · 내용`, 심각도(빨강 → 주황 → 회색) 순 정렬 (유형: 갱신 확인 필요 · 갱신 취소 예정 · 진행대기 장기 · 체험 종료 확인 필요 · 도입 지연 · 장비 미회수 · 미처리 문의 · 청구 미처리 · 미납)

- (장비관리 연동 후) 장비 재고 현황

### 4-15. 장비 (1차 범위)
- 1차는 **수량만 기록**: 계약 장비 수량 + 추가 기기 + 체험 장비 → 장비 탭에 기기별 합계, 회수 수량은 회수 체크리스트 값
- 장비 탭에 옵션상품 목록 표시 + [옵션상품 추가] (계약·비용 탭과 같은 데이터)
- 장비 탭 [수량 수정]: 계약 제공·체험 제공 수량을 표에서 직접 수정, 저장 시 계약 장비 수량에 반영 + 히스토리 기록 (추가 제공은 추가 기기 제공 내역 합산)
- 2차: [수량 수정] → [장비 관리에서 수정 →]으로 교체, 수량은 장비 매핑 결과로 결정
- 2차 장비관리 개발 시 같은 수량을 클릭하면 매핑된 장비 목록을 보여주도록 확장

## 5. 2차 — 장비관리 (범위 메모, 상세 정의는 추후)
- **매핑 흐름**: 장비 입고·등록 → 고객사 계약 시 장비 매핑 → 고객사 기기를 입소자에게 매핑
- 고객사 매핑은 **연속 번호 범위 단위**가 기본(예: 3대 → 101·102·103) → 범위 지정 일괄 매핑 UI 필요
- **장비 상태(안)**: 입고완료 · 서비스중 · 고장 · 수리중
  - 🟡 검토: 회수 후 소독·점검 대기 상태, 폐기 상태, 체험 제공 구분 추가 여부
- 1차에 기록한 고객사별 제공 수량과 2차 매핑 수량이 맞는지 대조 기능
